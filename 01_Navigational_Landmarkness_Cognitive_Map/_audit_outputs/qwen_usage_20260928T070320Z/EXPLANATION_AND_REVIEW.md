## 2. 模型实际看到的图像和文字

下表 step 沿用原 manifest 的从0计数。决策点为 step3；两条路线各有8个点，但本次未把8点完整演示给模型。

| 调用 | 图片输入 | 实际任务 |
|---|---|---|
| 阶段0 | 两条路线各自 step3 的单个固定视角 | 每张最多提议3个可见线索；测试JSON及坐标约定 |
| 阶段1 | 每条路线的 step2、3、4 各一张独立图片；main_03取view0，main_06取view1 | 6次独立单图候选提议；共16个候选 |
| 阶段2有序 | step0→1→2→4→5，各一张固定视角；再接step3四视角 | 共9图，一次请求内选择A或B |
| 阶段2无路线 | 只有step3四视角 | 共4图，选择A或B |
| 阶段2打乱 | step5→1→0→4→2，再接step3四视角 | 共9图，选择A或B |

每次请求是新建一条 user message。图像顺序由程序确定，只有打乱条件故意改变顺序；不是从全库随机抽图，也不是闭环行动后再取下一张。路线图像的标签是 route memory image 1..5，当前图标签是 current view_0..3。路径、panoid、经纬度、原step编号、正确出口和VLAD分数没有作为文本给模型。

候选提示的语义是：只根据图像提出最多3个清晰可见的地点/寻路线索，输出编号、0–1000坐标框、类别、描述、可能作用、可见性和不确定性；不要选择路线。

路线提示的语义是：你在路口，从两个合法非回头出口中选择，使用所给图像；有序条件把前面的图片当作视觉记忆，打乱条件说明图片已打乱，无路线条件只有当前四视角。main_03的A/B分别是直行/左转，main_06是右转/直行。该提示没有明确要求重走演示路线，也没有指定目的地。全文和七份实际请求的源哈希见同目录 `ACTUAL_QWEN_REQUESTS.md`、`request_evidence.json`。

固定view编号与路线行进方向不是一回事。绝对中心朝向仍是 `(heading_from_api + 90*view_index) mod 360`。已有正确heading不意味着模型已收到朝向，也不意味着view0永久就是前方。

## 3. 本地推理、API、网页

当前是在用户服务器上直接加载权重推理，不是调用托管API。API是一种调用接口，也可以部署在同一服务器上并调用同一套权重；它不代表另一种训练方法。托管API是否等价，须核对精确模型/版本、图像处理、提示、thinking、采样与数值精度；仅名称相似不能确认等价。网页版本和内部设置在本次审查中未确认，不能直接当成此9B运行的复现。网页适合探索提示，本项目以可记录输入和版本的运行方式做正式比较。

官方模型卡将Qwen3.5-9B标为预训练及后训练后的模型，并展示API部署。因此“我们没有微调”不等于“官方模型从未做过后训练”。此处不推断官方训练数据包含或不包含Paris。

## 4. 主任务应怎样收敛

0926研究设计已有明确主线：给定一段已经看过的短路线与新的路口观察，测试视觉线索是否帮助沿原路线续行。建议继续此任务：先示范短路线（经过路口并包含出口以后），再给从同一来向抵达该路口的新观察，要求选择继续原路线的出口。

示范图像应按真实路线顺序；测试图像及近重复需要留出并审计。所有条件使用相同测试观察、出口和评分标准；有序与打乱使用同一组示范图像，提示格式尽量一致，避免把不同措辞也变成条件差异。可以先在一次上下文中分学习段/测试段实现，这只检验上下文中的路线使用，不能宣称持久记忆或已经形成认知地图。

若是先示范再重走，示范中的路口后图像是允许的历史经历；不能一概当未来泄漏。若另做首次在线导航，测试时不得看到未来，而且需要目标或其他任务约束。不要仅删除step4/5就宣称修好了本次任务。

不看路线可作为移除路线信息的对照，但它没有足够信息判断研究者指定的路线；其匹配率只表示缺信息时的选择倾向，不能当公平的完整导航任务分数。最有针对性的地标比较是相同路线经历下的原图、候选遮挡和匹配控制遮挡。

## 5. 人工具体审核什么

先审核main_03、main_06，不必为理解本轮把15条候选全部重做。路线审核必须与候选框审核分开。

| 审核对象 | 人要判断什么 | 通过与存疑处理 |
|---|---|---|
| 短路线连贯性 | 顺序图是否能理解为沿街行进；是否有突跳/近重复；拍摄年份、施工、季相是否破坏关联 | 连贯可留；可修则ADAPT；看不清填UNSURE，交回机器核查 |
| 路口与观察方向 | 从哪里来、何时需要做选择；图中的前左右与所定义来向一致吗 | 必须以进入路口方向为基准，不凭view编号认方向 |
| 候选出口与通行方式 | 候选是不同且可通行的出口吗；步行还是驾车；标志和地图是否冲突 | 机动车单行/禁入不能自动充当步行约束；未确认不叫gold |
| 演示路线的正确出口 | 从演示路线的前后关系应接哪条路；A/B是否正确对应 | 合法出口可以有多个，只有延续所演示路线的出口是任务答案；不按Qwen回答改答案 |
| 学习/测试材料 | 测试图是否留出；是否能定位到该路口；提示和文件名是否直接透露答案 | 实质改图后需复核；不得为让模型答对而挑选路线 |
| 候选线索区域 | 真有其物吗；文字正确吗；框吻合吗；是否重复实体；临时车辆等是否稳定 | ACCEPT/EDIT/REJECT/UNCERTAIN；保留旧框和修订框；有用性仍待干预检验 |

旧路线审核入口：`../HUMAN_MINIMAL_REVIEW_GUIDE.md`；表：`../HUMAN_MINIMAL_CONFIRMATION.csv`。main_03需特别查看2012-06旧图与月份混用；main_06需检查季相和光照差异。现有表中ACCEPT只代表接受区域进入修正，不等于正式材料已经合格。对正确出口和通行模式的最终确认应另存新版本。

人不需要自己算heading或查全盘。机器先给地图、路线顺序板、当前四视角、来向和匿名出口标注，人只核查可理解性和歧义。候选“看起来有用”是审核假说，不是真正功能效应的标签。
