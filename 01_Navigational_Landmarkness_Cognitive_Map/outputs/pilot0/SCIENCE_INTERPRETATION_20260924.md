# Pilot 0 基线的科学解释

## 1. 当前研究问题

本项目不是要回答“哪个图像模型的地点检索准确率最高”，而是要回答：

> 街景中的哪些视觉或空间线索会成为导航有用、认知有用的地标，并如何作为认知地图的锚点，支持定位、定向、地点记忆和路线决策？

因此，Pilot 0 先建立一个可重复的测量层：给定空间上明确的 query/reference 关系，判断街景表示是否能利用图像中的信息恢复局部地点对应。之后再问某个可指认区域是否对这种对应有额外贡献，最后才进入路线选择和认知地图功能。

## 2. 当前 P/N/I 题库测量什么

- 44 个 query view，来自 12 个 pano 和 6 个道路组；168 个 reference view。
- 82 个 P：同一道路段、约 9.7--32.5 m 的人工确认近邻对应。
- 6160 个 N：不同道路段、约 88.6--1275.7 m 的空间对照。
- 1150 个 I：关系不够明确或位于缓冲边界，不进入正式排序。
- 每个 query 评分图库为固定 N 加 1--3 个 P，最多 140 个 N。

P 不是“地标图像”，N 也不是“没有地标的图像”。P 定义空间上应该接近的地点对应，N 提供模型必须区分的其他道路对照，I 用来避免把不确定关系强行当作假负例。一个 query 可以有多个 P，是因为附近多个视角都可能是有效地点对应；否则指标会受任意单一参考图选择影响。

当前题库适合做开发基线，但 N 与 P 的空间分离较大，任务可能主要测量道路或街区场景差异。它还没有充分测试同一道路上相距很近但位置不同的精细定位。因此，后续必须在不改动当前冻结版本的前提下，另建同道路近距离的困难负例版本。

## 3. DINOv2 + VLAD 实际做了什么

当前流程是：

```text
448×448 单视图
→ DINOv2 ViT-G/14
→ block 31 的 value 局部 patch 描述子
→ AnyLoc 固定 urban 32-center VLAD 聚合
→ 49152 维图像向量
→ query/reference 余弦相似度排序
```

G/14 权重和 urban VLAD centers 都是预训练或预先学习好的外部资产，本轮没有在 Paris 上重新训练或拟合。这个流程测量的是：

> 完整街景图像中是否存在足以支持地点对应的视觉模式。

这些模式可能来自建筑立面、道路结构、招牌、空间布局、材质或整体场景，但当前向量本身不能告诉我们究竟是哪一类线索起作用。它也不是目标检测器、地标分类器、路线规划器或认知地图模型。

## 4. 基线结果支持到什么程度

服务器完整执行并通过本地独立复算：

- Recall@1：42/44 = 95.45%
- Recall@5：43/44 = 97.73%
- Recall@10：43/44 = 97.73%
- margin 中位数：0.0994018；最小值 -0.06858
- 两个 Top-1 失败的最佳 P 排名为 2 和 11
- 删除边界例外后的 80P 敏感性结果完全相同
- 212 个 VLAD 向量、7392 个相似度和哈希均已核验，最大独立复算误差约 4.23e-7

这首先证明工程测量层是可靠的：固定数据、权重、词典、resize、特征和评分器可以稳定复现。科学上，它对“街景中存在可用于局部空间对应的视觉信息”提供了有限且任务依赖的支持；但由于当前 N 较容易，这不是对精细定位能力的强检验。

它尚未证明：

1. 模型使用了某个具体建筑、招牌或结构；
2. 某个候选区域具有 landmarkness；
3. 候选线索能帮助方向判断、道路选择或路线记忆；
4. 模型形成了认知地图；
5. 结果可推广到巴黎其他区域、其他城市或独立路线。

正例数量分层只能作为描述：1 个 P 的题目成功 6/8，2 个 P 的题目成功 34/34，3 个 P 的题目成功 2/2。因为 Recall 定义为“命中任意一个 P 即成功”，正例数直接影响指标，且与题目难度混杂，不能解释为正例越多 landmarkness 越强。

## 5. 下一步：从完整图像转向候选线索贡献

下一步不是立即把 Qwen 做成完整导航 agent，而是让它提出可检查的候选区域：

1. 对单张 query view 输入 640×640 原图；不输入 reference、P/N/I 标签、位置答案或 DINO 分数。
2. Qwen 输出结构化候选：`bbox`、类型、文字描述、可能的导航作用、可见性和提示版本。
3. 人工审核框是否真的可见、是否重复、是否描述准确，以及框坐标是否落在 640×640 画布内。
4. 为每个候选生成大小、形状和粗略位置匹配的控制区域。
5. 在固定 reference、冻结 P/N/I、固定 VLAD 词典和固定评分器下，只修改 query，比较完整图、删除候选、保留候选、删除控制区、保留控制区。

主要指标不是只看 Recall 是否下降，而是每个 query 的 `S_pos`、最高 N 相似度、margin、正例排名，以及候选区域效应相对于匹配控制区效应的差异。只有当候选区域的效应稳定地超过匹配控制、并在相关 pano 或邻近观察中可重复时，才能说它是“支持空间对应的候选线索”。这仍然不是完整地标标签；还需要后续导航功能实验。

实施上，现有 49152 维最终 VLAD 向量不足以单独执行 descriptor removal；但服务器返回的 `feature_index.csv` 已记录每张活动图的 `1024×1536`、row-major patch 特征文件，当前可以优先复用这批 patch cache。下一步应核验 patch 文件的完整性和与 VLAD 的对应关系，再冻结 640→448→32×32 的框映射、patch 覆盖规则和 mask 操作并抽样审计。只有在 patch cache 不完整时才需要重新前向。

## 6. Qwen 连续路径实验的位置

连续路径和“下一步怎么走”的指令属于后续功能性验证。合适的输入是短连续街景序列、起点观察、路线目标，以及可选的候选道路边；正式方向实验应使用按路线 bearing 重投影的 FOV=90°视图。

期望输出不是一句自由文本，而是结构化决策，例如：

```json
{
  "chosen_edge": "edge_17",
  "direction": "left",
  "landmark_candidates": [
    {"view_id": "...", "azimuth": 172.0, "role": "edge_selection"}
  ],
  "reason": "...",
  "uncertainty": 0.24
}
```

这一步测试的是候选线索是否支持道路选择、方向判断和路线解释。它与当前 DINOv2+VLAD 的关系是串联而非竞争：

```text
DINOv2+VLAD：测量视觉空间对应
Qwen 候选：提出可描述的视觉线索
区域干预：检验线索是否贡献空间对应
连续路径任务：检验线索是否支持导航决策
认知地图：组织地点、线索、方向和路线关系
```

因此，当前最准确的结论是：我们已经完成了一个可靠的空间对应测量参照，下一步要把“整幅图有效”分解为“哪些可指认线索有效”，再检验这些线索是否具有真正的导航和认知功能。
